# Bulk Plan Date Input Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users type the bulk planned date as `DD/MM/YYYY` or choose it from a calendar while keeping all application and Supabase values in `YYYY-MM-DD`.

**Architecture:** Add two focused date-conversion helpers beside the existing calibration-work date helpers. Render a text input as the user-facing control and a native date input as the calendar source; both feed the existing bulk-date update function only after strict normalization. No database interface changes.

**Tech Stack:** Browser JavaScript, HTML/CSS generated by `js/29-calibration-work.js`, existing browser test harness, PowerShell verification scripts, GitHub Pages service worker.

## Global Constraints

- The visible typed format is exactly `DD/MM/YYYY`.
- Wizard state and RPC payload dates remain exactly `YYYY-MM-DD`.
- Impossible dates are rejected without changing selected item dates.
- Existing selection and result-bearing-item safeguards remain unchanged.
- Individual instrument date controls are outside this change.

- [ ] **Step 3: Add strict conversion helpers**

Implement strict zero-padded day-first parsing and formatting:

```javascript
function cwParseDisplayDate(value) {
  const match = /^(\d{2})\/(\d{2})\/(\d{4})$/.exec(String(value || '').trim());
  if (!match) return '';
  const iso = match[3] + '-' + match[2] + '-' + match[1];
  const date = new Date(iso + 'T00:00:00Z');
  return cwValidISODate(iso)
    && date.getUTCFullYear() === Number(match[3])
    && date.getUTCMonth() + 1 === Number(match[2])
    && date.getUTCDate() === Number(match[1]) ? iso : '';
}

function cwFormatDisplayDate(isoDate) {
  return cwValidISODate(isoDate)
    ? isoDate.slice(8, 10) + '/' + isoDate.slice(5, 7) + '/' + isoDate.slice(0, 4) : '';
}
```
