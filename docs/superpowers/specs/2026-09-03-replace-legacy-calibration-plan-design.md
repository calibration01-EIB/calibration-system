# แทนที่ระบบแผนสอบเทียบเดิมด้วยชุดงานสอบเทียบ

วันที่: 3 กันยายน 2026

## เป้าหมาย

แทนที่ระบบ `frm_plans` และ `calibration_plans` เดิมด้วยโมดูลชุดงานสอบเทียบที่มีอยู่แล้วบน `calibration_work_batches` ให้เป็นเส้นทางใช้งานเพียงระบบเดียว ผู้ใช้เลือกเครื่องจากทะเบียน ดำเนินงานตามสถานะรายเครื่อง และเก็บเอกสารเป็น PDF สองช่วง โดยไม่มีการอ่าน สร้าง หรือนำเข้า Excel FRM1 อีกต่อไป

ชื่อเมนูหลักเปลี่ยนจาก **วางแผนสอบเทียบ** เป็น **แผนสอบเทียบ**

## ขอบเขตการแทนที่

- ลบ UI และ JavaScript ที่ใช้งาน `frm_plans`, `calibration_plans` และ `calibration_plan_items`
- ลบเมนูและข้อความ **แผน FRM** และ **ระบบเก่า**
- ลบความสามารถอ่าน สร้าง นำเข้า และส่งออก Excel FRM1
- ลบข้อมูลทดสอบ `frm_plans` จำนวน 3 รายการหลังตรวจจำนวนซ้ำใน production
- ลบตาราง, policy, trigger และ RPC ของระบบแผนเดิมเมื่อยืนยันแล้วว่าไม่มี dependency จากระบบอื่น
- คงระบบ `calibration_work_batches` และตารางลูกเป็นแหล่งข้อมูลเพียงชุดเดียว
- งานที่เสร็จหรือยกเลิกในระบบใหม่ต้องเก็บเป็นประวัติ ไม่ลบข้อมูลธุรกรรม

นอกขอบเขต: การเปลี่ยนแบบฟอร์มสอบเทียบเฉพาะประเภทเครื่องมือ และการย้ายข้อมูลทดสอบเดิมเข้าสู่ระบบใหม่

## ลำดับงาน

1. `Admin` หรือ `Editor` เลือกเครื่องหนึ่งหรือหลายรายการจากทะเบียน
2. สร้างชุดงานฉบับร่างและตรวจรายการ
3. ยืนยันชุดงาน ระบบล็อกเครื่องแบบ transaction เพื่อป้องกันเครื่องเดียวอยู่ในงานที่ยังเปิดมากกว่าหนึ่งชุด
4. แนบ **PDF ช่วงที่ 1 — เอกสารรับทราบ** จากหน่วยงาน
5. ดำเนินการรายเครื่อง:
   - บันทึกเลข Certificate และวันที่สอบเทียบ
   - แนบ Certificate PDF สำหรับรายการที่สอบเสร็จ หรือ Overdue PDF ตามกรณี
   - ข้ามรายการได้เมื่อระบุเหตุผล
6. เมื่อทุกรายการอยู่ในสถานะจบ ให้แนบ **PDF ช่วงที่ 2 — เอกสารปิดงาน**
7. ระบบปิดชุดงาน อัปเดตทะเบียนเครื่อง ปลดล็อก และบันทึก Audit ใน transaction เดียว
8. ชุดงานที่เสร็จหรือยกเลิกแสดงในประวัติพร้อมเอกสารและเหตุการณ์ทั้งหมด

## โครงสร้างหน้าจอ

หน้า **แผนสอบเทียบ** มีสี่แท็บ:

1. **เลือกเครื่อง** — ค้นหา กรอง เลือกหลายรายการ และแสดงว่าเครื่องใดถูกล็อก
2. **ชุดงาน** — แสดงเลขชุดงาน สถานะ ความคืบหน้า และการกระทำถัดไปที่ทำได้
3. **รอดำเนินการ** — แสดงคิวตามขั้นตอนปัจจุบัน ได้แก่ รอ PDF รับทราบ รอสอบเทียบ และรอ PDF ปิดงาน
4. **ประวัติ** — แสดงชุดงานที่เสร็จและยกเลิก พร้อม PDF และ Audit

หน้าจอต้องไม่มีตัวแก้ไขตาราง FRM1 และไม่มีเส้นทางกลับไปยังระบบแผนเดิม

## ข้อมูลและส่วนประกอบ

- `calibration_work_batches` เก็บหัวชุดงานและสถานะรวม
- `calibration_work_items` เก็บเครื่องมือ สถานะผล และ snapshot ของทะเบียน
- `calibration_work_instrument_locks` ป้องกันการเลือกเครื่องซ้ำขณะชุดงานเปิด
- `calibration_work_documents` เก็บ metadata และ version ของ PDF
- `calibration_work_audit` เก็บการเปลี่ยนสถานะ ผู้กระทำ และเหตุผล
- Supabase Storage bucket `calibration-work-batches` เก็บ PDF แบบ private
- การเขียนทั้งหมดใช้ RPC ที่ตรวจ session token และสิทธิ์ `Admin`/`Editor`

## เอกสาร PDF

- รองรับเฉพาะ MIME type `application/pdf`
- ขนาดสูงสุด 50 MB ต่อไฟล์
- PDF ช่วงที่ 1 เป็นเอกสารรับทราบและต้องมีให้ครบก่อนเริ่มขั้นสอบเทียบ
- PDF ช่วงที่ 2 เป็นเอกสารปิดงานและต้องมีให้ครบก่อนเปลี่ยนชุดงานเป็นเสร็จสมบูรณ์
- Certificate/Overdue PDF ผูกกับรายการเครื่องมือแต่ละรายการ
- เอกสารใหม่ใช้ version เพิ่มขึ้น ไม่เขียนทับไฟล์เดิม
- ห้ามใช้ Excel FRM1 ทุกเส้นทาง

## การจัดการข้อผิดพลาดและความสอดคล้อง

- การยืนยันชุดงาน ล็อกเครื่อง ปิดรายการ ปิดชุดงาน และอัปเดตทะเบียนทำแบบ transaction
- หากคำขอขาดการตอบกลับหรือเครือข่ายหลุด หน้าเว็บต้องโหลดสถานะจริงจากฐานก่อนอนุญาตให้ส่งซ้ำ
- ความขัดแย้งจากเครื่องถูกล็อกต้องระบุรายการเครื่องที่เป็นสาเหตุ
- ข้อผิดพลาดต้องแสดงข้อความภาษาไทยที่บอกขั้นตอนและสาเหตุ ห้ามใช้ข้อความรวมว่า “วางแผนไม่สำเร็จ”
- การลบระบบเดิมต้องหยุดทันทีหากจำนวน `frm_plans` ไม่เท่ากับ 3 หรือพบข้อมูล/dependency ที่ไม่อยู่ในแบบนี้

## การถอนระบบเดิมจากฐานข้อมูล

ใช้ migration ที่ตรวจเงื่อนไขก่อนทำลายข้อมูล:

1. ตรวจ `frm_plans = 3`, `calibration_plans = 0`, `calibration_plan_items = 0`
2. ตรวจ Foreign Key, view, trigger, policy และ function ที่อ้างถึงตารางเดิม
3. ถอน RPC, policy และ trigger ของระบบเดิมตามลำดับ dependency
4. ลบข้อมูลทดสอบและตารางเดิมด้วยชื่อเป้าหมายแบบเจาะจง
5. ตรวจหลัง migration ว่า object เดิมหายครบ และ object ของชุดงานใหม่ยังอยู่ครบ

ถ้า precondition ข้อใดไม่ตรง migration ต้อง raise exception และ rollback ทั้งชุด

## การทดสอบและเกณฑ์สำเร็จ

- Regression tests ยืนยันว่า UI ไม่มี `frm_plans`, `calibration_plans`, Excel FRM1, แท็บแผน FRM หรือระบบเก่า
- ทดสอบสี่แท็บและการมองเห็น action ตามสถานะ
- ทดสอบการสร้าง/ยืนยันชุดงาน การล็อกซ้ำ และการเพิ่ม/ถอดรายการก่อนยืนยัน
- ทดสอบ PDF สองช่วง ชนิดไฟล์ ขนาด version และสิทธิ์ดาวน์โหลด
- ทดสอบผลรายเครื่อง Certificate, Overdue, Skip และ Reset
- ทดสอบปิด/ยกเลิกชุดงาน การอัปเดตทะเบียน การปลดล็อก และ Audit
- ทดสอบ fail-closed เมื่อ token หมดอายุหรือ role ไม่ถูกต้อง
- ทดสอบ migration ใน transaction แบบ rollback ก่อน apply production
- รันชุดทดสอบทั้งระบบ การตรวจโหลดหน้า การตรวจ syntax และ `git diff --check`
- ตรวจ Supabase security/performance advisors หลัง migration

งานสำเร็จเมื่อ GitHub `main` และ Supabase production ใช้ระบบชุดงานใหม่เพียงระบบเดียว ผู้ใช้สามารถทำวงจร PDF สองช่วงจนจบได้ และไม่มีข้อมูล โค้ด หรือ database object ของระบบแผนเดิมหลงเหลือ
