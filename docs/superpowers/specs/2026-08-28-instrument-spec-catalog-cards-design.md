# Instrument Spec Catalog Cards Design

วันที่: 28 สิงหาคม 2026  
สถานะ: ผู้ใช้อนุมัติแนวทางแบบ A แล้ว รอตรวจสเปกก่อนจัดทำ implementation plan

## เป้าหมาย

เปลี่ยนเฉพาะแท็บ **มุมมองสเปก** ในหน้ารายการเครื่องมือจากตารางเป็นการ์ดแบบแคตตาล็อกสินค้า เพื่อให้มองหารหัสเครื่องมือและวันครบกำหนดได้เร็วขึ้น โดยคงแท็บ **บัญชีรายการ** และตารางรายละเอียดทุกคอลัมน์ไว้เหมือนเดิม

## ขอบเขต

- เปลี่ยน `#listSpecCard` จากตารางสเปกเป็น Grid Card
- คง `#listFullCard` และการ render บัญชีรายการเดิมทั้งหมด
- คงระบบค้นหา ตัวกรอง หมวด สถานะ การแบ่งหน้า และตัวเลือก `20 / 50 / 100`
- ใช้ modal รายละเอียดและสิทธิ์ผู้ใช้เดิม
- ใช้ระบบรูปเครื่องมือเดิมใน Supabase Storage โฟลเดอร์ `photos_<id>_<id_code>`
- ไม่เพิ่มชื่อประเภทหรือชื่อเครื่องมือบนการ์ด
- ไม่เพิ่มรูปจำลองหรือรูปมาตรฐานเมื่อรายการไม่มีรูป

## โครงสร้างการ์ด

เรียงจากบนลงล่าง:

1. **พื้นที่รูปภาพ** อัตราส่วนแนวนอนคงที่
   - ใช้รูปช่อง `overview` เป็นอันดับแรก
   - หากไม่มี `overview` ให้ใช้รูปแรกตามลำดับที่ระบบเดิมจัดไว้
   - หากไม่มีรูป ให้คงพื้นที่ภาพพื้นเรียบและแสดงข้อความเล็ก `ยังไม่มีรูปเครื่องมือ`
   - วาง Badge สถานะที่มุมขวาบนของพื้นที่ภาพ
2. **ID CODE** เป็นข้อความเด่นที่สุดของส่วนข้อมูล ตัวหนาและขนาดใหญ่
3. **Cert No.** หนึ่งบรรทัด ตัดข้อความด้วย ellipsis หากยาวเกินพื้นที่
4. **Due Date** หนึ่งบรรทัด โดยสีวันที่สัมพันธ์กับสถานะ
5. ปุ่ม **ดูรายละเอียด (Detail)** เต็มความกว้างส่วนล่าง

ตัวอย่างโครงสร้าง:

```text
┌─────────────────────────┐
│                         │
│       รูปแรกของเครื่อง    │  [สถานะ]
│                         │
├─────────────────────────┤
│ PFP3BB03-WI01           │
│ Cert: CAL-2026-001      │
│ Due: 24 ส.ค. 2027       │
│ [    ดูรายละเอียด    ]  │
└─────────────────────────┘
```

## สถานะและสี

- **ปกติ**: เขียว/เขียวน้ำทะเล
- **ใกล้ครบกำหนด**: เหลืองอำพัน
- **เลยกำหนด**: แดง
- **ยกเลิกสอบเทียบ**: เทากลาง
- Due Date ใช้สีเดียวกับสถานะ แต่ยังต้องมี contrast อ่านง่าย
- สถานะต้องมีข้อความ ไม่พึ่งสีเพียงอย่างเดียว

## Layout และ Responsive

- Desktop: 4 การ์ดต่อแถว
- Tablet: 2 การ์ดต่อแถว
- Mobile: 1 การ์ดต่อแถว
- Grid ต้องไม่เกิด horizontal overflow
- ความสูงพื้นที่รูปและส่วนข้อมูลต้องสม่ำเสมอ เพื่อให้ปุ่ม Detail อยู่แนวเดียวกัน
- เมื่อผู้ใช้เลือกแท็บบัญชีรายการ ให้กลับไปแสดงตารางเดิมโดยไม่เปลี่ยนข้อมูลหรือคอลัมน์

## Interaction

- คลิกปุ่ม `ดูรายละเอียด` เปิด `openInstrumentDetail(id)` เดิม
- คลิกพื้นที่การ์ดเปิดรายละเอียดเช่นเดียวกัน ยกเว้นองค์ประกอบที่มี action เฉพาะ
- รองรับคีย์บอร์ด: การ์ดหรือปุ่มต้องเข้าถึงด้วย Tab และเปิดด้วย Enter/Space
- มี hover/focus ที่เข้มพอให้ติดตามรายการได้ง่าย แต่ไม่ทำให้ตำแหน่งการ์ดขยับ
- การเปลี่ยนตัวกรอง หน้า และจำนวนรายการ ต้อง render การ์ดจากชุดข้อมูลเดียวกับบัญชีรายการ

## รูปภาพและประสิทธิภาพ

- ไม่เพิ่มคอลัมน์รูปใหม่ในตาราง `instruments`
- ใช้โฟลเดอร์รูปเดิมและเลือกภาพปกด้วยกติกาเดียวกับหน้ารายละเอียด
- โหลดรูปเฉพาะการ์ดที่เข้าใกล้ viewport (lazy loading)
- Cache URL/ผลลัพธ์รูปตาม instrument ระหว่าง session และล้างหรือ refresh หลังเพิ่ม ลบ หรือแก้รูป
- จำกัดคำขอรูปให้สัมพันธ์กับหน้าปัจจุบัน ไม่โหลดรูปของข้อมูลทั้งหมด 2,272 รายการ
- หากโหลดรูปไม่ได้ ให้แสดงสถานะไม่มีรูปโดยไม่ทำให้รายการทั้งหมดล้มเหลว
- Signed URL หมดอายุต้องขอใหม่ได้โดยไม่ต้อง refresh หน้าเว็บทั้งหน้า

## Empty, Loading และ Error States

- ระหว่างรอรูป ใช้พื้นหลังเรียบหรือ skeleton เบา ๆ ที่ไม่กระพริบ
- ไม่มีรูป: `ยังไม่มีรูปเครื่องมือ`
- ไม่มีผลการค้นหา: ใช้ข้อความ `ไม่พบข้อมูล` เดิม
- โหลดรูปผิดพลาด: แสดงพื้นที่ว่างเหมือนไม่มีรูป และไม่แสดงภาพแตก

## การทดสอบและเกณฑ์สำเร็จ

- มุมมองสเปกแสดงการ์ด 4/2/1 คอลัมน์ตาม viewport
- การ์ดไม่มีชื่อเครื่องมือหรือข้อความ `Electronic Balance`
- รูป `overview` หรือรูปแรกปรากฏเป็นภาพปก และรายการไม่มีรูปแสดง placeholder
- ID Code เด่นกว่า Cert No. และ Due Date
- Badge และ Due Date แสดงสถานะถูกต้องสำหรับปกติ ใกล้ครบ เลยกำหนด และยกเลิก
- ปุ่มและการ์ดเปิดรายละเอียดรายการที่ถูกต้อง
- Search, filters, pagination และ 20/50/100 ยังทำงานเหมือนเดิม
- บัญชีรายการไม่เปลี่ยนโครงสร้างหรือพฤติกรรม
- ไม่เกิด horizontal overflow ที่ Mobile, Tablet และ Desktop
- การ์ดหนึ่งใบโหลดรูปผิดพลาดแล้วการ์ดอื่นยังใช้งานได้

## นอกขอบเขต

- เปลี่ยนหน้ารายละเอียดเครื่องมือ
- เปลี่ยนฟอร์มอัปโหลดหรือแก้ไขรูป
- เปลี่ยนฐานข้อมูลหรือย้าย Storage bucket
- เปลี่ยนหน้าบัญชีรายการ
- เพิ่มการสั่งซื้อ ราคา ตะกร้า หรือพฤติกรรมร้านค้าอื่น
