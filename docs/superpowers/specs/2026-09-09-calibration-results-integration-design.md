# ออกแบบการรวม “ติดตามผลสอบเทียบ” เข้า “แผนสอบเทียบ”

วันที่: 2026-09-09  
สถานะ: ผู้ใช้อนุมัติแนวทางแบบที่ 1 แล้ว

## เป้าหมาย

ลดเมนูที่ซ้ำซ้อน โดยคงความสามารถและข้อมูลของหน้าติดตามผลสอบเทียบเดิมไว้ทั้งหมด แล้วนำมาเป็นแท็บที่ 5 ชื่อ **ผลและใบรับรอง** ภายในหน้า **แผนสอบเทียบ** ผู้ใช้จึงทำงานตั้งแต่เลือกเครื่อง สร้างชุดงาน ติดตามสถานะ ไปจนถึงแนบใบรับรองที่เซ็นแล้วได้ในหน้าเดียว

การเปลี่ยนแปลงนี้เป็นการปรับโครงสร้างหน้าจอและเส้นทางเท่านั้น ไม่ลบตาราง `calibration_records` ประวัติการสอบเทียบ หรือไฟล์ PDF/ไฟล์สแกนใน Storage

## ขอบเขตหน้าจอ

หน้าแผนสอบเทียบมีแท็บหลักเรียงดังนี้

1. เลือกเครื่อง
2. ชุดงาน
3. รอดำเนินการ
4. ประวัติ
5. ผลและใบรับรอง

แท็บ **ผลและใบรับรอง** ใช้ส่วนติดต่อเดิมของหน้าติดตามผลสอบเทียบ ได้แก่

- การ์ดสรุปสถานะ
- ตัวกรองและช่องค้นหา
- ความคืบหน้ารายเครื่อง
- ผลสอบเทียบที่บันทึกไว้
- การเปิดประวัติรายเครื่อง
- การแนบไฟล์สแกนใบรับรองที่เซ็นแล้ว
- การเปิดดูไฟล์ที่แนบไว้

หัวเรื่องใหญ่ของหน้าแผนสอบเทียบยังคงเป็น “แผนสอบเทียบ” ส่วนหัวภายในแท็บใช้ชื่อ “ผลและใบรับรอง” พร้อมปุ่มรีเฟรชเฉพาะข้อมูลผลสอบเทียบ

เมื่อเลือกแท็บนี้ ระบบซ่อนพื้นผิวของชุดงาน (`cwNotifications`, ตัวกรองชุดงาน, metrics, รายการและรายละเอียดชุดงาน) แล้วแสดงพื้นผิวผลและใบรับรองแทน เมื่อกลับไปแท็บชุดงาน ระบบคืนพื้นผิวเดิมและสถานะแท็บ/รายการเดิม โดยไม่เปิดหน้าซ้ำซ้อน

## การนำทางและความเข้ากันได้

ลบทางเข้าที่ซ้ำซ้อนดังนี้

- เมนูด้านข้าง “ติดตามผลสอบเทียบ”
- การ์ด “ติดตามผลสอบเทียบ” บนหน้าแรก
- รายการ “ติดตาม” ในแถบนำทางมือถือ
- การ์ดลัดหรือ action อื่นที่เปิด `showPage('calrecs')`

ทางเข้าที่เกี่ยวข้องทั้งหมดจะชี้ไปหน้า `plan` และเลือกแท็บ `results` แทน

เพื่อไม่ให้ลิงก์หรือโค้ดเดิมเสีย `showPage('calrecs')` ยังคงรับค่าได้ แต่ทำหน้าที่เป็น alias: เปิดหน้า `plan` แล้วเลือกแท็บ **ผลและใบรับรอง** โดยเมนูที่แสดง active ต้องเป็น “แผนสอบเทียบ” ทั้งบนเดสก์ท็อปและมือถือ

การกดรายการแจ้งเตือน “รอแนบสแกน” จากกระดิ่งจะเปิดหน้าแผนสอบเทียบ เลือกแท็บผลและใบรับรอง และเลือกตัวกรอง `scan` เพื่อให้ผู้ใช้เห็นรายการที่ต้องดำเนินการทันที

## โครงสร้างการทำงาน

เพิ่มค่า `results` ในสถานะแท็บหลักของ `29-calibration-work.js` แต่ไม่แมปค่านี้เข้ากับแท็บสถานะชุดงาน (`active`, `waiting`, `history`) เพราะเป็นพื้นผิวคนละชุด

เพิ่ม container สำหรับผลและใบรับรองภายใน `pagePlan` และย้าย markup ของ `pageCalrecs` เดิมเข้า container นี้ โดยเก็บ id ขององค์ประกอบภายใน เช่น `calrecTiles`, `calrecStatus`, `calrecBody` และ modal ประวัติเดิมไว้ เพื่อใช้ logic ใน `23-cal-records.js` ต่อได้โดยไม่สร้างสำเนาใหม่

ฟังก์ชันสลับแท็บหลักต้องรับผิดชอบการแสดงผลสองพื้นผิว:

- `select`, `batches`, `waiting`, `history`: แสดงส่วนชุดงานและซ่อนผล/ใบรับรอง
- `results`: ซ่อนส่วนชุดงาน แสดงผล/ใบรับรอง และเรียก `loadCalrecsPage()` หลังข้อมูลทะเบียนเครื่องมือพร้อม

การโหลดหน้า `plan` ตามปกติยังโหลด snapshot ของชุดงานเพื่อให้สถานะร่วมและ badge ถูกต้อง หากหน้าถูกเปิดผ่าน alias `calrecs` ต้องรักษา `results` เป็นแท็บที่ร้องขอ ไม่ให้การโหลด async สลับกลับไป `batches`

## Badge และการแจ้งเตือน

ใช้ badge เดียวที่ `navPlanBadge` และเลิกใช้ `navCalrecsBadge` โดย badge แสดงผลรวมขององค์ประกอบสองค่า:

- จำนวนชุดงานที่ยังไม่ `completed` หรือ `cancelled`
- จำนวน `calibration_records` สถานะ `issued` ที่รอแนบไฟล์สแกน

ผู้ผลิตข้อมูลแต่ละชุดบันทึกค่า component ของตัวเอง แล้วเรียก renderer กลางให้รวมและแสดงผล วิธีนี้ป้องกัน `cwPublishPlanBadge()` และ `renderPendingCertWidget()` เขียนทับกันตามลำดับการตอบกลับของ async request

ตัวเลขในกระดิ่งยังแสดงเฉพาะจำนวนใบรับรองที่รอแนบสแกนตามเดิม เพื่อให้ความหมายของการแจ้งเตือนไม่เปลี่ยน ส่วนการ์ดหน้าแรกและ dashboard ที่อ้าง `navPlanBadge` จะได้รับค่ารวมโดยอัตโนมัติ

## ข้อมูล สิทธิ์ และข้อผิดพลาด

- ไม่มี migration และไม่มีการลบข้อมูล
- อ่านและอัปเดต `calibration_records` ด้วยเงื่อนไขสิทธิ์เดิม
- การแนบไฟล์สแกนยังอนุญาตเฉพาะ `admin` และ `editor`
- ผู้ใช้ที่อ่านได้อย่างเดียวต้องยังค้นหา ดูผล ประวัติ และเปิดไฟล์ตามสิทธิ์เดิมได้
- หากโหลดชุดงานสำเร็จแต่โหลดผลสอบเทียบไม่สำเร็จ ให้แสดงข้อผิดพลาดเฉพาะในแท็บผลและใบรับรอง ไม่ทำให้หน้าแผนสอบเทียบส่วนอื่นใช้ไม่ได้
- หลังแนบไฟล์สำเร็จ ให้รีเฟรชรายการเมื่อแท็บ `results` เปิดอยู่ และอัปเดต badge/กระดิ่งทันที

## การทดสอบและเกณฑ์ยอมรับ

เพิ่มหรือแก้ automated tests ให้ครอบคลุมอย่างน้อย:

1. หน้าแผนสอบเทียบมีแท็บ “ผลและใบรับรอง” และ keyboard navigation เข้าถึงได้
2. ไม่มีเมนู/การ์ดหน้าแรก/เมนูมือถือ “ติดตามผลสอบเทียบ” แยกต่างหาก
3. `showPage('calrecs')` เปิด `plan` และเลือก `results`
4. การแจ้งเตือนรอแนบสแกนเปิดแท็บ `results` พร้อมตัวกรอง `scan`
5. สลับระหว่าง `results` กับแท็บชุดงานแล้วแสดง/ซ่อน container ถูกต้อง
6. การโหลด async ของหน้า plan ไม่สลับแท็บ `results` กลับเอง
7. badge เมนูแผนสอบเทียบเท่ากับผลรวมสอง component และไม่ขึ้นกับลำดับ async
8. ผู้ใช้ viewer ไม่เห็น action แนบไฟล์ ส่วน admin/editor ยังแนบได้
9. โหลดข้อมูลผิดพลาดในแท็บหนึ่งไม่ทำให้พื้นผิวอีกชุดเสีย
10. ชุดทดสอบเดิมทั้งหมดและ app-load smoke test ผ่าน

ตรวจใช้งานจริงทั้ง desktop และ mobile โดยครอบคลุมการเปิดจากเมนูแผนสอบเทียบ การเปิดจากกระดิ่ง ลิงก์เก่า `calrecs` การค้นหา/กรอง การเปิดประวัติ และการแนบ/เปิด PDF ใบรับรอง

## สิ่งที่ไม่ทำในงานนี้

- ไม่เปลี่ยนลำดับการทำงานของชุดงานสอบเทียบ
- ไม่เปลี่ยนรูปแบบ PDF สองช่วงที่ตกลงไว้
- ไม่รวมตาราง `calibration_records` เข้ากับตารางชุดงานในฐานข้อมูล
- ไม่ลบประวัติหรือไฟล์เดิม
- ไม่เปลี่ยนกฎ RLS หรือสิทธิ์ผู้ใช้
