# Instrument Edit Tabbed Form Design

วันที่อนุมัติแนวทาง: 2026-08-20
สถานะ: อนุมัติทิศทางภาพแบบ B แล้ว รอผู้ใช้ตรวจสเปกก่อนจัดทำแผนลงมือ

## เป้าหมาย

ปรับหน้าต่าง “เพิ่ม/แก้ไขเครื่องมือ” ให้ข้อมูลแบ่งเป็นหมวดชัดเจนและเห็นช่องภายในหมวดเดียวกันพร้อมกันมากขึ้นที่ Browser zoom 100% โดยไม่เปลี่ยนข้อมูล การตรวจสอบ หรือกระบวนการบันทึกเดิม

ภาพอ้างอิงที่ผู้ใช้เลือก: [instrument-edit-tabbed-form-v1.png](../../prototypes/instrument-edit-tabbed-form-v1.png)

## การตัดสินใจหลัก

- ใช้แท็บแนวนอน 3 หมวดแทนฟอร์มยาวและแทนแถบหมวดด้านซ้าย
- แสดงเนื้อหาเพียงแท็บที่เลือก หมวดอื่นต้องไม่กินพื้นที่และไม่ปรากฏต่อด้านล่าง
- ใช้กริด 3 คอลัมน์บนเดสก์ท็อปเพื่อให้ช่องของหมวดเดียวกันอยู่ในจอพร้อมกันมากที่สุด
- ส่วนหัว แถบแท็บ และแถบปุ่มด้านล่างต้องอยู่คงที่ ให้เลื่อนเฉพาะพื้นที่เนื้อหากลางเมื่อจำเป็น
- ใช้ modal เดิมร่วมกันทั้งโหมด “เพิ่มเครื่องมือ” และ “แก้ไขเครื่องมือ”

## โครงสร้างหน้าต่าง

### 1. Modal shell

- ความกว้างเดสก์ท็อป: `min(1400px, calc(100vw - 48px))`
- ความสูงสูงสุด: `calc(100vh - 48px)`
- พื้นหลังตารางเดิมยังมองเห็นอย่างจางผ่าน overlay สีเทาเข้ม
- Modal แบ่งเป็น 4 ส่วน: sticky header, sticky tab bar, scrollable content, sticky footer
- ไม่ปรับ global scale ของแอปและไม่เปลี่ยนขนาดองค์ประกอบนอก `#instrumentModal`

### 2. Header

- ด้านซ้ายแสดงชื่อ “เพิ่มเครื่องมือ” หรือ “แก้ไขเครื่องมือ” ตามโหมดเดิม
- เมื่อแก้ไข ให้แสดงชิป `ID Code` ปัจจุบันข้างชื่อเพื่อยืนยันว่ากำลังแก้รายการใด
- ด้านขวาแสดงสถานะที่ไม่รบกวนสายตาและปุ่มปิด
- กล่องเตือนข้อมูลซ้ำเป็นข้อความระดับ modal อยู่ใต้ tab bar เพื่อให้มองเห็นได้จากทุกแท็บ

### 3. Tab bar

แท็บมี 3 รายการ:

1. ข้อมูลเครื่องมือ
2. สเปกการวัด
3. การสอบเทียบ

แท็บที่ active ใช้พื้น aqua อ่อน เส้นหรือขอบ teal และข้อความ teal เข้ม ส่วนแท็บ inactive ใช้พื้นขาวและข้อความ navy/gray ทุกแท็บแสดงเลขหมวด ไอคอน และชื่อหมวด พร้อมข้อความ “หมวด X จาก 3” และ progress indicator ขนาดเล็กด้านขวา

การทำงาน:

- เปิด modal ทุกครั้งที่แท็บ 1
- คลิกแท็บแล้วเปลี่ยนเฉพาะ panel ที่แสดง ค่าที่กรอกในแท็บอื่นต้องคงอยู่
- ปุ่มแท็บเป็น `<button>` จริง ใช้ `role="tablist"`, `role="tab"`, `aria-selected`, `aria-controls` และ panel ใช้ `role="tabpanel"`
- รองรับ `ArrowLeft`, `ArrowRight`, `Home` และ `End` สำหรับเปลี่ยนแท็บด้วยแป้นพิมพ์
- focus ring ต้องชัดเจนและใช้สี teal ตามธีม

### 4. Content grid

- เดสก์ท็อปตั้งแต่ 1200px: 3 คอลัมน์
- แท็บเล็ต 768–1199px: 2 คอลัมน์
- มือถือต่ำกว่า 768px: 1 คอลัมน์และ modal เต็มหน้าจอตามรูปแบบ app mode ปัจจุบัน
- Input/select สูงประมาณ 44–48px ช่องว่างแนวนอนและแนวตั้ง 14–16px
- Label อยู่เหนือ control และไม่ใช้พื้นที่แนวตั้งเกินจำเป็น
- ใช้เครื่องหมาย required เฉพาะช่องที่ logic ปัจจุบันบังคับจริง เพื่อไม่ให้ภาพสื่อการตรวจสอบผิดจากระบบ

## เนื้อหาแต่ละแท็บ

### แท็บ 1: ข้อมูลเครื่องมือ

เดสก์ท็อปจัด 12 ช่องเป็น 4 แถว × 3 คอลัมน์ตามลำดับ:

1. ประเภทเครื่องมือ | กลุ่มสินค้า | ชื่อเครื่องมือ
2. รหัสเครื่องจักร | ID Code | Serial No.
3. ยี่ห้อ | รุ่น | หน่วยงาน
4. แผนก | Cost Center | Asset No.

Hint ของหน่วยงานยังแสดงใต้ช่องหน่วยงานโดยไม่ทำให้กริดแถวอื่นกระโดด

### แท็บ 2: สเปกการวัด

- แถวหลัก: พิกัด Max, ย่านการวัด, ประเภทเครื่องชั่ง
- กลุ่มค่าหลายช่วงใช้แถวเต็มความกว้างแบบ compact: ความละเอียด, Tolerance, ใช้งานต่ำสุด, ใช้งานสูงสุด
- แต่ละแถวหลายช่วงคง input ช่วง 1/2/3 และ unit selector เดิม
- แถวท้าย: ความถี่ใช้งาน และ Type A/B/C
- คงความสัมพันธ์ช่วง 1/2/3 และการแปลงหน่วยเดิมทุกประการ

### แท็บ 3: การสอบเทียบ

เดสก์ท็อปจัดเป็นกริด 3 คอลัมน์:

1. ความถี่สอบเทียบ | ภายใน/ภายนอก | สถานที่
2. เลขที่ Certificate | วันที่สอบเทียบ | วันครบกำหนด
3. Cert รอบก่อน | วันสอบรอบก่อน | Remark

ช่อง read-only ใช้พื้นเทาอ่อนและยังคงการคำนวณวันครบกำหนด/ข้อมูลรอบก่อนแบบเดิม

## Footer และสถานะการบันทึก

- Footer อยู่คงที่ด้านล่างเสมอ
- ด้านซ้ายแสดงข้อความช่วย “ตรวจสอบข้อมูลก่อนบันทึก”
- ด้านขวาเรียงปุ่ม “ยกเลิก” และปุ่มหลัก “บันทึก”/“บันทึกการแก้ไข”
- ขณะบันทึก ปุ่มหลัก disabled และแสดง “กำลังบันทึก...” ตาม flow เดิม
- การปิด modal, toast สำเร็จ/ล้มเหลว, reload ข้อมูล และ highlight แถวหลังบันทึกยังทำงานเหมือนเดิม

## Data flow และขอบเขตการเปลี่ยนแปลง

- คง `id` ของ input/select เดิมทั้งหมด เพื่อให้ `openInstrumentModal()`, `saveInstrument()`, duplicate check, unit parsing และ date calculation ทำงานต่อโดยไม่เปลี่ยน contract
- เพิ่ม state ฝั่ง UI สำหรับ active tab เท่านั้น ไม่มี schema หรือข้อมูลใหม่ในฐานข้อมูล
- การสลับแท็บเป็น presentation state และต้องไม่ reset ค่าในฟอร์ม
- หากบันทึกไม่ได้เพราะ ID Code ว่าง ให้เปิดแท็บ 1 และ focus ช่อง ID Code
- Duplicate warning ต้องยังมองเห็นจากทุกแท็บ; ไม่เปลี่ยนกฎตรวจ ID Code/CERT ซ้ำ

## Visual design

- สีหลัก teal `#079e91`, ตัวอักษร navy เข้ม, พื้นขาว และพื้นหลัง blue-gray อ่อน
- Card/panel ใช้เส้นขอบบางและเงาอ่อน ไม่ใช้ gradient, glassmorphism หรือภาพตกแต่ง
- Active/focus/hover ต้องแยกจากกันชัดเจนและคง contrast อ่านง่าย
- รูปแบบต้องกลมกลืนกับ HOME และหน้ารายการเครื่องมือที่ปรับแล้ว

## Accessibility

- ลำดับ tab ด้วยแป้นพิมพ์: ปิด → แท็บ → controls ของ panel ที่ active → footer actions
- Panel ที่ inactive ใช้ `hidden` หรือเทียบเท่าเพื่อไม่ให้ focus เข้าไปได้
- ปุ่มปิดและปุ่มแท็บมี accessible name
- เคารพ `prefers-reduced-motion`; transition ใช้เฉพาะสี/ขอบและไม่เกิน 160ms

## Error handling

- การบันทึกผิดพลาดยังใช้ toast เดิมและต้องคืนสถานะปุ่มบันทึกใน `finally`
- หาก duplicate check ล้มเหลว ให้คงข้อมูลทุกแท็บไว้และแสดง error เดิม
- การเปลี่ยนแท็บต้องไม่เรียกฐานข้อมูลและไม่มี loading state
- ไม่เพิ่ม autosave หรือ unsaved-changes confirmation ในงานนี้

## การทดสอบและเกณฑ์ยอมรับ

1. Modal เปิดที่แท็บ 1 ทั้งโหมดเพิ่มและแก้ไข
2. แสดงเพียง panel ของแท็บที่ active และค่าที่กรอกไม่หายเมื่อสลับแท็บ
3. เดสก์ท็อปที่ Browser 100% เห็นช่อง 12 ช่องของแท็บ 1 พร้อมกันโดยไม่ต้องเลื่อนภายใน panel
4. 3/2/1-column responsive ทำงานโดยไม่มี horizontal overflow
5. Header, tab bar และ footer อยู่คงที่ขณะเลื่อน panel ที่ยาว
6. Mouse และ keyboard ใช้สลับแท็บได้ พร้อม ARIA state ถูกต้อง
7. การโหลดค่าเดิม, hint หน่วยงาน, multi-band values, unit conversion, due-date calculation และ previous-cert autofill ยังทำงาน
8. กรณี ID Code ว่าง/ซ้ำ, CERT ซ้ำ, database error และ save success ยังให้ผลตาม flow เดิม
9. เพิ่มและแก้ไขรายการได้จริงโดย payload เดิมครบทุก field
10. Test suite เดิม, JavaScript syntax check และ app-load verification ผ่าน

## นอกขอบเขต

- เปลี่ยนฐานข้อมูลหรือ payload
- เพิ่ม/ลบช่องหรือเปลี่ยน validation rule
- ปรับสเกลทั้งเว็บไซต์
- ปรับหน้ารายการ ตาราง หรือ modal อื่น
- Autosave, wizard แบบบังคับลำดับ, และ unsaved-change guard
