# Calibration Work Batch Design

วันที่: 31 สิงหาคม 2026  
สถานะ: ผู้ใช้อนุมัติแนวทางและรายละเอียดการออกแบบแล้ว รอตรวจ design spec ก่อนจัดทำ implementation plan

## เป้าหมาย

สร้างโมดูล **ชุดงานสอบเทียบ** ใหม่ แยกจากระบบแผน FRM และระบบแผนเก่า เพื่อรองรับกระบวนการทำงานด้วยเอกสารกระดาษที่นำไปให้หน่วยงานลงนามแล้วสแกน PDF กลับเข้าระบบ โดยติดตามความคืบหน้าระดับชุดงานและรายเครื่องมือได้จากหน้าบัญชีรายการ

กระบวนการหลัก:

```text
เลือกเครื่องมือ
→ ยืนยันรายการแผน
→ แนบ PDF แผนที่หน่วยงานเซ็นรับทราบ
→ รอ/ดำเนินการสอบเทียบ
→ ลง Cert No. + วันที่สอบเทียบ + ใบ Cert รายเครื่อง
→ แนบ PDF แผนที่หน่วยงานเซ็นยืนยันหลังจบ
→ สอบเทียบสำเร็จ
```

## ขอบเขต

- สร้างโมดูลและโครงสร้างข้อมูลใหม่ ไม่ใช้ workflow อนุมัติออนไลน์ของ FRM เป็นแกน
- ผู้ใช้เลือกเครื่องมือเข้าชุดงานเอง ระบบไม่สร้างหรือเลือกแผนอัตโนมัติ
- หนึ่งชุดงานมีเครื่องมือจาก **1 หน่วยงานและ 1 ประเภทเครื่องมือ** เท่านั้น
- กำหนดวันที่ตามแผนแยกรายเครื่อง แม้อยู่ในชุดงานเดียวกัน
- เก็บ PDF รับทราบก่อนเริ่มงานและ PDF ยืนยันหลังจบในระดับชุดงาน
- เก็บใบ Certificate และเอกสารกรณีเลยกำหนดในระดับรายเครื่อง
- แสดงสถานะชุดงานและสถานะรายเครื่องในโมดูลใหม่และหน้าบัญชีรายการ
- อัปเดต Cert No. และวันที่สอบเทียบกลับข้อมูลเครื่องมือเมื่อผลรายเครื่องสมบูรณ์
- ไม่แก้ไข Due Date ของเครื่องมือ

## นอกขอบเขต

- การอนุมัติหรือรับทราบออนไลน์
- ลายเซ็นดิจิทัล

- การสร้างหรือเลือกแผนอัตโนมัติ
- การคำนวณหรือแก้ไข Due Date
- การย้ายหรือยกเลิกระบบแผน FRM เดิม
- การแก้ไขไฟล์ PDF ภายในระบบ

- เปิดหรือดาวน์โหลด PDF และใบ Certificate

## การจัดกลุ่มและการป้องกันรายการซ้ำ

- ก่อนเลือกเครื่องมือ ผู้ใช้ต้องเลือกหน่วยงานและประเภทเครื่องมือ
- ระบบแสดงเฉพาะเครื่องมือที่ตรงทั้งสองค่า
- ระบบไม่ให้เลือกเครื่องมือที่อยู่ในชุดงานอื่นซึ่งยังไม่สำเร็จหรือยังไม่ยกเลิก
- รายการที่เลือกไม่ได้ต้องแสดงเลขและชื่อชุดงานที่กำลังล็อกเครื่องมือนั้น
- เมื่อชุดงานสำเร็จ ถูกยกเลิก หรือเอาเครื่องออกตามกติกา เครื่องจึงกลับมาเลือกได้
- ต้องบังคับ uniqueness ที่ฐานข้อมูลเพื่อป้องกันการเลือกซ้ำจากสองหน้าจอพร้อมกัน ไม่พึ่งการซ่อนใน UI เพียงอย่างเดียว

## การสร้างชุดงาน

หน้าสร้างแบ่งเป็น 3 ช่วง:

### 1. กำหนดกลุ่ม

- เลือกหน่วยงาน
- เลือกประเภทเครื่องมือ
- ระบบโหลดเครื่องมือที่เข้าเงื่อนไขและสถานะการถูกล็อก

### 2. เลือกเครื่องมือและวันที่

- ติ๊กเลือกเครื่องมือเอง
- ค้นหาด้วย ID Code หรือชื่อเครื่องมือ
- กำหนดวันที่ตามแผนรายเครื่อง
- รองรับกำหนดวันที่เดียวให้หลายรายการแล้วแก้เฉพาะรายการได้
- ต้องมีวันที่ตามแผนครบทุกรายการก่อนยืนยัน

### 3. ตรวจสอบและยืนยัน

- แสดงเลขชุดงาน หน่วยงาน ประเภท จำนวนเครื่อง และวันที่ตามแผนทั้งหมด
- เมื่อยืนยันแล้ว ล็อกค่ากลุ่มและรายการเครื่องมือ
- สถานะเปลี่ยนจาก `draft` เป็น `awaiting_acknowledgement_pdf`
- เปิดช่องแนบ PDF รับทราบแผน

## สถานะระดับชุดงาน

| Key | ข้อความ | กติกา |
|---|---|---|
| `draft` | ร่าง | ยังแก้กลุ่ม รายการ และวันที่ได้ |
| `awaiting_acknowledgement_pdf` | รอแนบแผนรับทราบ | ยืนยันรายการแล้ว แต่ยังไม่มี PDF รับทราบฉบับใช้งาน |
| `awaiting_calibration` | รอสอบเทียบ | มี PDF รับทราบฉบับใช้งานแล้ว และยังไม่มีรายการเสร็จ |
| `partially_completed` | ดำเนินการบางส่วน | มีอย่างน้อยหนึ่งรายการเสร็จหรือข้าม แต่ยังไม่ครบทุกเครื่อง |
| `awaiting_closure_pdf` | รอแนบแผนยืนยัน | ทุกรายการเสร็จหรือถูกข้ามพร้อมเหตุผลแล้ว |
| `completed` | สอบเทียบสำเร็จ | มี PDF ยืนยันหลังจบฉบับใช้งานแล้ว |
| `cancelled` | ยกเลิกชุดงาน | ยกเลิกพร้อมเหตุผลและปลดล็อกเครื่องมือ |

สถานะต้องเปลี่ยนจากข้อมูลจริงของรายการและเอกสาร ไม่ให้ผู้ใช้เลือก key สถานะโดยตรง

## สถานะระดับรายเครื่อง

| Key | ข้อความ | กติกา |
|---|---|---|
| `in_progress` | กำลังสอบเทียบ | มี PDF รับทราบแล้ว ผลยังไม่ครบ และยังไม่เลยวันที่ตามแผน |
| `overdue` | เกินแผนสอบเทียบ | ผลยังไม่ครบและวันนี้เลยวันที่ตามแผน |
| `completed` | เสร็จแล้ว | Cert No., วันที่สอบเทียบ, ใบ Cert และหลักฐานเลยกำหนดเมื่อจำเป็นครบ |
| `skipped` | ไม่ได้ดำเนินการ | Editor/Admin เลือกข้ามและกรอกเหตุผลแล้ว |

`overdue` เป็นสถานะคำนวณ ไม่ใช่ค่าที่ผู้ใช้กดเลือก เมื่อข้อมูลผลครบจะเป็น `completed`

## เอกสารระดับชุดงาน

### PDF รับทราบแผน

- แนบได้เมื่อยืนยันรายการแผนแล้ว
- ต้องเป็น PDF
- เป็นประตูเปิดให้ลงผลรายเครื่อง
- การแทนไฟล์สร้างเวอร์ชันใหม่และเก็บไฟล์เดิม
- เก็บผู้แนบ วันเวลา ชื่อไฟล์ ขนาด และ SHA-256 hash

### PDF ยืนยันหลังจบ

- แนบได้เมื่อทุกรายการเป็น `completed` หรือ `skipped`
- ก่อนแนบต้องแสดงหน้าสรุป Cert No., วันที่สอบเทียบ และเหตุผลรายการที่ข้าม
- แนบสำเร็จแล้วชุดงานเป็น `completed`
- การแทนไฟล์หลังปิดแผนต้องกรอกเหตุผล สร้างเวอร์ชันใหม่ และบันทึก audit

## ผลสอบเทียบและเอกสารรายเครื่อง

Editor/Admin สามารถบันทึกร่างของช่องต่อไปนี้ได้:

- Cert No.
- วันที่สอบเทียบ
- ใบ Certificate PDF

รายการจะเป็น `completed` เมื่อช่องบังคับครบและการอัปเดตข้อมูลเครื่องมือสำเร็จ

### เอกสารกรณีเลยกำหนด

ต้องแสดงและบังคับเมื่ออย่างใดอย่างหนึ่งเป็นจริง:

- วันนี้เลยวันที่ตามแผนและรายการยังไม่เสร็จ
- วันที่สอบเทียบจริงช้ากว่าวันที่ตามแผน

ข้อมูลบังคับ:

- เหตุผลที่เลยกำหนด
- เอกสารกรณีเลยกำหนด PDF

แม้ Cert No., วันที่สอบเทียบ และใบ Cert ครบ รายการต้องยังไม่เป็น `completed` จนกว่าเหตุผลและเอกสารเลยกำหนดจะครบ

หากวันที่สอบเทียบจริงไม่เกินวันที่ตามแผน ไม่บังคับเอกสาร แม้ผู้ใช้จะบันทึกข้อมูลย้อนหลังหลังวันตามแผน

## การอัปเดตบัญชีรายการ

เมื่อผลรายเครื่องสมบูรณ์ ระบบต้องเรียก RPC เดียวซึ่งทำ transaction เพื่อ:

1. ตรวจสิทธิ์ผู้ใช้
2. ตรวจว่ารายการยังอยู่ในชุดงานและยังไม่เสร็จ
3. ตรวจข้อมูลบังคับและเอกสาร
4. อัปเดต `instruments.cert_no`
5. อัปเดต `instruments.cal_date`
6. ไม่แก้ `instruments.due_date`
7. ทำเครื่องหมายรายการเป็น `completed`
8. บันทึก audit

ถ้าขั้นตอนใดล้มเหลว ต้อง rollback ทั้งชุดและรายการต้องไม่ขึ้น “เสร็จแล้ว”

## การแก้ไขหลังยืนยัน

### ก่อนมี PDF รับทราบ

- เพิ่มหรือลบเครื่องมือได้
- เปลี่ยนวันที่ตามแผนได้
- ต้องคงกติกาหนึ่งหน่วยงานและหนึ่งประเภท

### หลังมี PDF รับทราบ

การเพิ่ม ลบเครื่อง หรือเปลี่ยนวันที่ตามแผนต้อง:

1. ให้ Editor/Admin กรอกเหตุผล
2. บันทึก audit พร้อมค่าก่อนและหลัง
3. เก็บ PDF รับทราบเดิมในประวัติ
4. ยกเลิก flag ฉบับใช้งานของ PDF เดิม
5. เปลี่ยนสถานะชุดงานกลับ `awaiting_acknowledgement_pdf`
6. ห้ามลงผลต่อจนกว่าจะแนบ PDF รับทราบฉบับใหม่

หากเครื่องมีผลหรือใบ Cert แล้ว ห้ามนำออกจนกว่าจะใช้คำสั่งล้างผลที่ต้องกรอกเหตุผลและทำ audit

## การข้ามรายการ

- ใช้เมื่อเครื่องมือนั้นไม่ได้ดำเนินการในชุดงานนี้
- ต้องกรอกเหตุผล
- รายการเปลี่ยนเป็น `skipped`
- ไม่อัปเดต Cert No., วันที่สอบเทียบ หรือ Due Date ของเครื่องมือ
- รายการที่ข้ามถือว่า resolved สำหรับการเปิดช่อง PDF ปิดแผน
- รายการที่ข้ามยังคงอยู่ใน PDF สรุปปิดแผนพร้อมเหตุผล

## การเก็บไฟล์และเวอร์ชัน

ใช้ Storage bucket ที่กำหนดสำหรับโมดูลใหม่ โดยจัด path แยกตามชุดงานและรายการ เช่น:

```text
calibration-work-batches/<batch_id>/batch/acknowledgement/v0001.pdf
calibration-work-batches/<batch_id>/batch/closure/v0001.pdf
calibration-work-batches/<batch_id>/items/<item_id>/certificate/v0001.pdf
calibration-work-batches/<batch_id>/items/<item_id>/overdue/v0001.pdf
```

ทุกการแนบไฟล์ต้องสร้าง record เอกสารที่มี:

- `batch_id`
- `item_id` เมื่อเป็นเอกสารรายเครื่อง
- `document_kind`
- `storage_path`
- `version_number`
- `is_current`
- `original_filename`
- `mime_type`
- `file_size`
- `uploaded_by`
- `uploaded_at`
- `replacement_reason` เมื่อแทนไฟล์

ห้ามลบเวอร์ชันเก่าจากหน้าจอปกติ

## โครงสร้างข้อมูล

### `calibration_work_batches`

- `title text not null`
- `unit_code text not null`
- `instrument_type text not null`
- `status text not null`
- `created_by text not null`
- `created_at timestamptz not null`
- `confirmed_by text`
- `confirmed_at timestamptz`

- `completed_at timestamptz`
- `cancelled_by text`
- `cancelled_at timestamptz`

### `calibration_work_items`

- `id uuid primary key`
- `batch_id uuid not null`
- `instrument_id bigint not null`
- `planned_date date not null`
- `result_status text not null`
- `cert_no text`
- `calibration_date date`
- `overdue_reason text`
- `skip_reason text`
- `completed_by text`
- `completed_at timestamptz`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

### `calibration_work_instrument_locks`

- `instrument_id bigint primary key`
- `batch_id uuid not null`
- `item_id uuid not null unique`
- `locked_at timestamptz not null`

RPC เพิ่มเครื่องต้องสร้าง lock ใน transaction เดียวกับ item ค่า primary key ของ `instrument_id` ป้องกันเครื่องเดียวอยู่ใน active batch มากกว่าหนึ่งชุด เมื่อเอาเครื่องออก ยกเลิกชุดงาน หรือปิดชุดงาน RPC ต้องลบ lock ใน transaction เดียวกัน

### `calibration_work_documents`

เก็บเอกสารและเวอร์ชันตามหัวข้อการเก็บไฟล์ โดย `item_id` เป็น null สำหรับเอกสารระดับชุดงาน

### `calibration_work_audit`

- ชุดงาน

- action

## UI และการนำทาง

เพิ่มหน้าหลัก **ชุดงานสอบเทียบ** โดยไม่ทับหน้าวางแผน FRM เดิม

แท็บหลัก:

- ชุดงานที่กำลังดำเนินการ
- รอเอกสาร
- เสร็จสิ้น
- ประวัติทั้งหมด

ข้อมูลสรุป:

- จำนวนชุดงานกำลังดำเนินการ
- จำนวนเครื่องเสร็จจากทั้งหมด
- จำนวนเครื่องเกินแผน
- จำนวนชุดงานรอ PDF ปิดแผน

หน้ารายละเอียดชุดงาน:

- ส่วนหัวเลขชุดงาน หน่วยงาน ประเภท และความคืบหน้า
- ตารางหรือการ์ดสถานะรายเครื่อง
- เอกสารระดับชุดงาน
- ประวัติกิจกรรม
- การกระทำตามสถานะและสิทธิ์

Responsive:

- Desktop ใช้รายการเครื่องเป็นพื้นที่หลักและเอกสารชุดงานเป็น side panel
- Tablet ลดความกว้างและจัด panel ตามพื้นที่
- Mobile เรียงเป็นคอลัมน์เดียวและยังลงผล/แนบไฟล์ได้ครบ
- ห้ามเกิด horizontal overflow นอก container ตารางที่จำเป็น

## สถานะในหน้าบัญชีรายการ

เครื่องมือที่อยู่ในชุดงาน active ต้องแสดง:

- เลข/ชื่อชุดงาน
- วันที่ตามแผน
- สถานะรายเครื่อง
- ทางลัดเปิดรายละเอียดชุดงาน

ลำดับความสำคัญของสถานะแสดงผล:

1. เสร็จแล้ว
2. เกินแผนสอบเทียบ
3. กำลังสอบเทียบ
4. อยู่ในชุดงานแต่รอ PDF รับทราบ
5. ไม่มีชุดงาน

การแสดงสถานะไม่เปลี่ยนตัวกรองหรือโครงสร้างบัญชีรายการที่ไม่เกี่ยวข้อง

## การแจ้งเตือนภายในระบบ

- ชุดงานที่รอ PDF รับทราบ
- เครื่องที่ถึงวันที่ตามแผนวันนี้
- เครื่องที่เกินแผนและยังขาดเหตุผลหรือเอกสาร
- ชุดงานที่ผลครบแต่ยังไม่มี PDF ปิดแผน

ไม่มีอีเมลหรือการแจ้งเตือนภายนอกในขอบเขตนี้

## Error Handling และความสอดคล้องของข้อมูล

- ตรวจ MIME type, extension และขนาดไฟล์ก่อนอัปโหลด รับเฉพาะ PDF ขนาดไม่เกิน 50 MB ต่อไฟล์
- สร้าง document record หลังอัปโหลดสำเร็จและจัดการไฟล์กำพร้าหาก transaction ล้มเหลว
- ความผิดพลาดของไฟล์หนึ่งรายการต้องไม่ทำให้รายการอื่นใช้ไม่ได้
- ใช้ signed URL อายุสั้นเพื่อเปิดเอกสารและขอใหม่ได้เมื่อหมดอายุ
- ป้องกัน double-submit และใช้ optimistic concurrency เมื่อแก้ชุดงาน
- ตรวจ constraint ซ้ำที่ฐานข้อมูล ไม่เชื่อข้อมูลจาก browser
- การคำนวณสถานะใช้ timezone ของระบบ `Asia/Bangkok`
- แสดงข้อความผิดพลาดเฉพาะรายการและให้ลองใหม่โดยไม่ต้องโหลดหน้าทั้งหมด
- การแทนไฟล์ต้องไม่เปลี่ยน `is_current` จนกว่าไฟล์ใหม่และ record ใหม่สำเร็จครบ

## เกณฑ์สำเร็จและการทดสอบ

### การสร้างและจัดกลุ่ม

- ผู้ใช้เลือกเครื่องมือเอง
- ชุดงานหนึ่งมีหน่วยงานและประเภทเดียว
- เครื่องเดียวอยู่ใน active batch ได้เพียงชุดเดียว
- วันที่ตามแผนครบทุกรายการก่อนยืนยัน
- เครื่องที่ถูกล็อกแสดงชุดงานเจ้าของ lock

### เอกสารและ workflow

- ลงผลไม่ได้ก่อนมี PDF รับทราบฉบับใช้งาน
- แก้รายการหลังมี PDF แล้วทำให้กลับไปรอ PDF ฉบับใหม่
- PDF ทุกชนิดเก็บเวอร์ชัน ผู้แนบ วันเวลา และเหตุผลแทนไฟล์
- ปิดชุดงานไม่ได้ก่อนรายการทั้งหมด resolved
- สถานะ completed เกิดหลังแนบ PDF ปิดแผนเท่านั้น

### ผลรายเครื่อง

- ขาด Cert No., วันที่ หรือใบ Cert แล้วไม่เป็น completed
- รายการเลยกำหนดต้องมีเหตุผลและ PDF เลยกำหนด
- วันที่สอบเทียบไม่เกินแผนไม่บังคับหลักฐานเลยกำหนด
- รายการ skipped ต้องมีเหตุผล
- การ complete อัปเดต Cert No. และวันที่กลับ instruments
- Due Date เดิมไม่เปลี่ยน
- transaction ล้มเหลวแล้วสถานะและข้อมูลเครื่องมือต้องไม่เปลี่ยนครึ่งเดียว

### สิทธิ์

- Editor/Admin ดำเนิน workflow ได้
- Viewer/Owner อ่านและดาวน์โหลดได้เท่านั้น
- การเรียก API/RPC โดยไม่มีสิทธิ์ต้องถูกปฏิเสธแม้ข้าม UI

### UI และความทนทาน

- สถานะแสดงถูกต้องทั้งโมดูลและบัญชีรายการ
- รองรับ Desktop, Tablet และ Mobile
- ไม่มี horizontal overflow ที่ไม่ตั้งใจ
- ไฟล์หนึ่งรายการผิดพลาดแล้วรายการอื่นยังทำงานได้
- signed URL หมดอายุแล้วเปิดใหม่ได้โดยไม่ refresh ทั้งหน้า
- audit แสดงลำดับกิจกรรมและเหตุผลครบ
