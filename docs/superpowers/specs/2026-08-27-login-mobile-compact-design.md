# Login Mobile Compact Design

วันที่: 27 สิงหาคม 2026  
สถานะ: อนุมัติแนวทางการออกแบบแล้ว รอตรวจสเปกก่อนเริ่ม implementation

## เป้าหมาย

ทำหน้า Login รุ่น Mobile ให้กระชับลงทางสายตาประมาณ 20% โดยปรับขนาดองค์ประกอบจริงด้วย CSS ไม่ใช้ `transform: scale()` และไม่เปลี่ยนหน้า Desktop หรือพฤติกรรมการเข้าสู่ระบบ

## ขอบเขต

- ใช้กับ viewport กว้างไม่เกิน `820px`
- มีการปรับละเอียดเพิ่มเติมสำหรับ viewport กว้างไม่เกิน `420px`
- คงภาพ Hero, สี, Frosted Glass, โลโก้ ILC และโครงสร้างข้อมูลเดิม
- คงการซ่อนข้อความ Editorial Brand บน Mobile ตามพฤติกรรมปัจจุบัน
- ไม่แก้ API, credential flow, `doLogin()`, Enter key, password visibility toggle หรือข้อความผิดพลาด
- หน้า Desktop ตั้งแต่ `821px` ขึ้นไปต้องไม่เปลี่ยนขนาดหรือการจัดวาง

## การปรับขนาด

### การ์ด

- ลด padding และระยะห่างภายในประมาณ 20%
- ความสูงตามเนื้อหาเป้าหมายประมาณ `380–400px` จากปัจจุบันประมาณ `460px`
- ความกว้างยังเป็นแบบ fluid เพื่อรองรับข้อความภาษาไทย โดยเพิ่ม gutter ด้านข้างให้การ์ดแคบลงเล็กน้อย
- วางการ์ดช่วงบนของ Hero เหมือนเดิม ไม่บังคับยืดเต็มความสูง

### โลโก้และข้อความ

- โลโก้ ILC กว้างเป้าหมายประมาณ `190px`
- ลดระยะด้านล่างโลโก้ประมาณ 20%
- ลดขนาด label, placeholder และข้อความช่วยเหลือเล็กน้อย แต่ต้องยังอ่านได้ชัดเจนที่ 320px

### ช่องกรอกและปุ่ม

- Username, Password และปุ่มเข้าสู่ระบบสูงเป้าหมาย `46px`
- ปุ่มแสดง/ซ่อนรหัสผ่านต้องมีพื้นที่กดอย่างน้อย `44px`
- ลด padding แนวนอนและระยะระหว่าง field ตามสัดส่วน
- Focus ring, hover state, disabled state และ error state ต้องทำงานเหมือนเดิม

### กล่องช่วยเหลือ

- ลด padding, margin และขนาดตัวอักษรประมาณ 20%
- ต้องแสดงข้อความสองบรรทัดครบ: `พบปัญหาในการเข้าสู่ระบบ` และ `ติดต่อผู้ดูแลระบบ 7401, 7402`

## Responsive และ Accessibility

- ห้ามเกิด horizontal overflow ที่ความกว้าง `320px`
- เนื้อหาทั้งหมดต้องอยู่ภายในขอบการ์ด
- ช่องกรอกต้องยังอ่าน placeholder ได้ และ password toggle ต้องไม่ทับข้อความ
- Tab focus และ keyboard login ต้องทำงานได้ตามเดิม
- ไม่ใช้การย่อทั้ง container เพราะจะทำให้ข้อความเบลอและ hit area ไม่ตรงกับภาพ

## การทดสอบ

- เพิ่ม regression assertions สำหรับค่าขนาด Mobile ใหม่ใน `tests/login-b3-ui.test.html`
- รันชุดทดสอบ HTML เดิมทั้งหมด
- ตรวจ syntax ของ JavaScript และ `sw.js`
- ตรวจภาพและขอบเขตจริงที่:
  - `320×800`
  - `360×800`
  - `390×844`
  - `430×932`
  - `768×900`
- ตรวจว่า Desktop `1280×720` ไม่มีการเปลี่ยนแปลงที่ไม่ตั้งใจ

## เกณฑ์สำเร็จ

- Mobile ดูกระชับลงประมาณ 20% และการ์ดสูงประมาณ `380–400px`
- Controls สูง `46px` และ password toggle มี hit area อย่างน้อย `44px`
- ไม่มีแนวนอนล้นใน viewport ที่กำหนด
- Desktop คงรูปแบบเดิม
- ชุดทดสอบทั้งหมดผ่าน และ cache version ถูกปรับเมื่อไฟล์ production เปลี่ยน
