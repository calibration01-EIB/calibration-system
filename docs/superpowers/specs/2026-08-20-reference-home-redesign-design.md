# Reference HOME Redesign Design

## Goal

ปรับ Header และหน้า HOME ของระบบปัจจุบันให้มีหน้าตาและการจัดวางเหมือน `C:\Users\8014\Desktop\Calibration App (offline).html` โดยรักษาฟังก์ชัน ข้อมูล สิทธิ์ผู้ใช้ และการนำทางของระบบเดิมทั้งหมด

## Scope

- ปรับ Header ที่แสดงหลังเข้าสู่ระบบ
- ปรับเนื้อหา HOME ทั้งแบนเนอร์และกริดการ์ดเมนู
- รองรับ Desktop, Tablet และ Mobile
- คงหน้า Login, Splash Screen และหน้าฟังก์ชันอื่นไว้ตามเดิม
- ไม่ฝังหรือนำ bundle จากไฟล์อ้างอิงมาใช้ในระบบจริง

## Architecture

ใช้โครงสร้างเดิมของเว็บแบบ static HTML/CSS/JavaScript และถอดแบบอ้างอิงลงในองค์ประกอบที่มีอยู่ แทนการนำแอปในไฟล์อ้างอิงมาฝังทั้งชุด วิธีนี้ทำให้ `showPage()`, การกำหนดสิทธิ์, Badge แจ้งเตือน และข้อมูลผู้ใช้ยังทำงานผ่านโค้ดเดิม

ความรับผิดชอบของไฟล์:

- `index.html` เป็นโครงสร้าง semantic ของ Header และ HOME
- `theme-aqua.css` เป็นรูปแบบ สี ระยะห่าง กริด สถานะ hover/focus และ responsive layout
- `js/24-home.js` เป็นข้อมูลการ์ด การแสดง Badge การซิงก์ผู้ใช้ เมนูผู้ใช้ และการนำทาง
- `tests/` เก็บการตรวจโครงสร้างและพฤติกรรมที่ต้องรักษา

## Header Design

Header ใช้พื้นขาว ขอบล่างบาง และติดด้านบนเหมือนไฟล์อ้างอิง ด้านซ้ายแสดงตราและชื่อ ILC ซึ่งกดกลับ HOME ได้ ด้านขวาประกอบด้วยปุ่ม HOME, กระดิ่งพร้อมจำนวนแจ้งเตือน, ปุ่มช่วยเหลือ และข้อมูลผู้ใช้พร้อมเมนูแบบ dropdown

ชื่อและบทบาทผู้ใช้ต้องอ่านจากระบบปัจจุบัน เมนูผู้ดูแลและ Audit ต้องแสดงตามสิทธิ์เดิม ปุ่ม Logout ต้องเรียก flow เดิม ปุ่มทุกตัวต้องมี focus state และ label ที่เครื่องมือช่วยการเข้าถึงอ่านได้

## HOME Design

HOME ใช้พื้นหลังเทาอ่อนและความกว้างเนื้อหาสูงสุดตามแบบอ้างอิง ส่วนบนเป็น hero/banner สำหรับระบบสอบเทียบ จากนั้นเป็นกริดการ์ดเมนูหลัก

การ์ดแต่ละใบประกอบด้วยภาพหรือ SVG, ชื่อเมนู, คำอธิบาย, ลูกศร และ Badge แบบไดนามิกเมื่อมีรายการที่ต้องดำเนินการ ลำดับและปลายทางใช้ชุดเมนูปัจจุบัน ได้แก่ Dashboard, รายการเครื่องมือ, ติดตามผลสอบเทียบ, ลำดับเลข Cert, ใบ Cert Reference, วางแผนสอบเทียบ, ใบบันทึกประจำวันเครื่องชั่ง, งานซ่อม, นำของออกนอกสถานที่ และสอบเทียบตุ้มน้ำหนัก

การกดการ์ดต้องเรียก `showPage()` ด้วยปลายทางเดิม โดยไม่มีการเปลี่ยน schema ข้อมูลหรือ business logic

## Responsive Behavior

- Desktop: Header แบบเต็มและกริด HOME 4 คอลัมน์
- Tablet: Header ย่อระยะห่างและกริด 2 คอลัมน์
- Mobile: Header จัดองค์ประกอบให้ไม่ล้น ป้ายข้อความรองที่ไม่จำเป็นย่อหรือซ่อน และกริด 1 คอลัมน์
- การ์ดต้องไม่ตัดชื่อหรือคำอธิบาย และพื้นที่กดต้องเหมาะกับการสัมผัส

## Data and Interaction Flow

1. หลังเข้าสู่ระบบ โค้ดเดิมกำหนดชื่อ บทบาท และสิทธิ์ผู้ใช้
2. `js/24-home.js` ซิงก์ข้อมูลดังกล่าวเข้าสู่ Header ใหม่
3. `renderAxTiles()` สร้างการ์ดจากรายการเมนูส่วนกลาง
4. `syncAxTileBadges()` อ่านจำนวนจาก Badge เดิมที่ระบบอัปเดตอยู่
5. การกด Header หรือการ์ดส่งต่อไปยัง `showPage()` เดิม

## Error and Fallback Handling

- ถ้าภาพการ์ดโหลดไม่ได้ ให้ใช้ SVG สำรองที่มีอยู่
- ถ้าชื่อหรือบทบาทยังไม่พร้อม ให้แสดงค่ากลางที่ไม่ทำให้ layout พัง
- ถ้าต้นทาง Badge ไม่มีอยู่ ให้ซ่อน Badge แทนการแสดงค่าไม่ถูกต้อง
- เมนูที่ยังไม่พร้อมใช้ยังคงเข้าหน้า placeholder ตามพฤติกรรมเดิม

## Testing

เพิ่มการตรวจแบบ test-first สำหรับ:

- Header มีองค์ประกอบและ hook ที่จำเป็นครบ
- HOME มีการ์ดครบตามลำดับและทุกการ์ดชี้ปลายทางเดิม
- Badge, user sync และ fallback image ยังทำงาน
- หน้าอื่นและ Login ไม่ถูกเปลี่ยนพฤติกรรม
- ตรวจภาพจริงที่ Desktop และ Mobile พร้อมตรวจ console error หลังเข้าสู่ HOME

## Acceptance Criteria

- Header และ HOME มีองค์ประกอบ สี ระยะห่าง ลำดับ และ responsive behavior ตรงกับไฟล์อ้างอิงในระดับที่มองเห็นได้
- ฟังก์ชัน Header, สิทธิ์ผู้ใช้, Badge, Logout และการนำทางทุกการ์ดยังทำงานเหมือนระบบเดิม
- ไม่มี console error ใหม่
- การทดสอบเดิมและการทดสอบ HOME/Header ใหม่ผ่านทั้งหมด
- ไม่แก้ business logic หรือหน้าอื่นนอกขอบเขตนี้
